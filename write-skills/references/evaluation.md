# Check discovery and delivery

Choose ordinary requests, including a neighboring job for which the entry offers no benefit. Before editing the skill, reserve a different real request to check transfer. Fix the input, competing entries and recipient's acceptance criteria before examining outputs. Include allowed alternatives that a narrow grader might reject.

Give workers the ordinary request. Leave skill names, instructions to look for guidance, and evaluator notes out of the brief and workspace. A request to edit a skill can name the artifact being edited. Verify which entries the harness actually offers. Compare with a matched workflow that omits the candidate to estimate the benefit of installing it. To isolate a metadata change, hold the body fixed.

Count an intentional read when the body reaches the worker before the decision it should affect. Confirm the returned content matches the intended edition. Record a different file with the same name, a failed lookup, a bulk read, and a late read separately. Assess every deliverable, including those from workers who skipped the body. When feasible, blind the assessor to the condition. Exercise the artifact through its recipient's entry point. Report failures, extra work, costs, and how many distinct tasks and repeat attempts the comparison covers.

Before adding a rule after a failure, identify what the worker could have observed and which action should have changed. If the body already directs that action, check whether it reached the worker and whether they carried it out. Keep the incident in the evaluation record. Use the reserved request before claiming the change transfers.
