# Naming skills in this collection

Name a job only after deciding that reusable instructions belong in a skill. “How should we fix this recurring failure?” may yield an enforcement change, an answer from a maintained source, or a decision for the owner. Those results generate no skill name.

1. Name the group of jobs after checking its boundaries. For a conditional commission, use the work due on the branch that warrants the skill. Keep the other outcomes in its description. A decision about proceeding is part of the method when it determines whether to produce the requested artifact. Give that decision its own group only if there is also a commission for a decision others can receive and use independently.
2. Choose the verb by the accepted result. A written report of a choice still delivers a choice. Distinguish defining a rule for future cases, applying a settled rule, and discovering what happened in one case. If the request leaves this distinction open and it changes placement, identify the missing fact. Do not coin a separate name for an ambiguity.
3. Use the object that the common method inspects or changes. Substitute a different medium, topic or artifact subtype. Drop the narrower term if the deciding observation, action and recipient's check all survive.
4. Join the verb and object with a hyphen. Use both preferred forms as printed below, lowercase with spaces replaced by single hyphens. Count nouns here take their listed plural, mass nouns their listed form. Add no article, vendor prefix, or word for the person doing the work. Use that exact identifier for both the folder and the `name` field. The description carries useful alternate terms and the cue that separates this job from its neighbors.

These are independent lists of senses and preferred English words for the recorded work.

For an uncovered sense, first use a preferred term in an applicable domain or project vocabulary. If that gives none, propose one with the case it includes, the closest case it excludes, and the source terms it replaces. Record the preferred spelling once before claiming repeatable names for that sense. A new synonym alone does not expand the vocabulary. If distinct jobs would have the same identifier, look for a difference in the accepted decision or object and bind a distinguishing term to that sense. Avoid numbering the collision or silently merging jobs. Check the resulting identifier against the package format, including its 64-character limit.

Check the identifier in the catalogs where it will be used. When another installed copy has that name, verify which file the worker actually receives. For a rename, update the callers that depend on the old identifier.
